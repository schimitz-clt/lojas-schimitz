# SCH-002 — Hardening + E-commerce Core

Relatório final. **Não inicia SCH-003 automaticamente.**

## 1. O que foi corrigido
- Rate limiting global (`ThrottlerGuard`) + limites mais rígidos em login/cadastro/refresh/pedido
- Reserva de estoque atômica (`UPDATE ... WHERE available >= qty`) contra corrida
- Cupom: `reservedCount` no checkout; `usedCount` só quando pago
- Pedido não pago não consome cupom em definitivo
- Cancelamento libera reserva e cupom
- Expiração de reserva (30 min) via `reservationExpiresAt`
- Preços/frete/desconto recalculados no backend
- Respostas de erro com `success` + `ok` e códigos
- Validação de senha (letras + números, mín. 8)
- Catálogo paginado (`page` / `pageSize`)

## 2. O que foi implementado
- `InventoryService` atômico
- `AuditService` (sem senha/token)
- Idempotency-Key no POST `/orders`
- `POST /orders/:publicId/cancel`
- `markPaid` / `expireReservations` (base para SCH-003)
- `PaymentProvider` nulo (TODO Mercado Pago)
- `ShippingProvider` nulo (legado); produção: frete grátis em Porto Alegre via CEP 90
- Checkout no front (`/checkout`)
- SEO: title/OG, robots, sitemap
- Testes unitários de transição de pedido e estoque disponível

## 3. O que já estava funcionando
- Auth Argon2 + JWT + refresh rotacionado
- Carrinho user/guest
- Catálogo, endereços, favoritos, reviews
- Helmet, ValidationPipe whitelist
- Docker Postgres + Redis

## 4. Pendente (proposital)
- Integração Mercado Pago (SCH-003)
- Frete real / Melhor Envio (SCH-004)
- Admin profissional (SCH-005)
- Testes E2E com banco
- Cookie HttpOnly de refresh em produção (dev ainda usa body JSON)

## 5. Problemas encontrados na auditoria
- Throttler declarado sem APP_GUARD
- Reserva de estoque com increment sem cláusula de disponibilidade
- usedCount incrementado em pedido ainda não pago
- Sem cancelamento / expiração
- Sem idempotência
- Lista de produtos sem paginação explícita no contrato
