# SCH-002.1 — Concorrência, idempotência e integridade

Não inicia SCH-003. Sem Mercado Pago.

## Problemas encontrados
- Idempotency-Key checada fora de UNIQUE por usuário (corrida).
- IdempotencyRecord quase não usado.
- Mesma chave com payload diferente não era rejeitada.
- Cancel/expire/markPaid: read-then-write (corrida).
- Cupom increment sem `WHERE used+reserved < max`.
- Release de estoque podia ser chamado duas vezes (GREATEST mascarava).
- `revokedAt` existia e era ignorado.

## Correções
- `@@unique([userId, idempotencyKey])`
- Insert condicional em IdempotencyRecord + hash do payload
- `IDEMPOTENCY_KEY_REUSED` se payload divergir
- Transição `UPDATE Order SET status=X WHERE id AND status='awaiting_payment'`
- Reserva/liberação/cupom atômicos
- Refresh só aceita `revokedAt IS NULL`; logout preenche `revokedAt`
